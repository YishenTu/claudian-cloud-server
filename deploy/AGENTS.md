# Deployment

- Keep shared deployment artifacts for self-hosted and managed installations. Operator ingress configuration stays outside these artifacts.
- Linux host networking keeps the application's loopback listener on host loopback. Do not add Compose port publication or widen the bind address to accommodate container networking.
- Real environment files and credentials stay outside the checkout and image; committed placeholder examples may enter the build for verification. Runtime uses a numeric unprivileged user, read-only root filesystem, dropped capabilities, and a stop grace period longer than the application shutdown budget.
- Configuration initialization and fresh-volume bootstrap are explicit privilege exceptions: they need ownership/provisioning access. Keep those short-lived operations separate from the application and maintenance runtimes.
- Mount claim-custody keys only for operations that open or verify protected custody. Keep the migration URL separate from runtime credentials and provide it only to schema initialization or clean-restore work. Do not broaden unrelated service mounts or credentials for wiring convenience.
- PostgreSQL and the authority volume form one persistent restart unit. Bootstrap's pending pairing marker permits completion of only that exact interrupted initialization; an unexplained one-sided database/volume pair fails closed. Runtime never provisions roles or applies schema.
- Startup completes environment restore recovery before the Project recovery gate. Project recovery needs its exact key and artifact dependencies; the online server does not need backup/export artifact roots or migration credentials.
- Source-based deployment resolves one immutable candidate and verifies authority before recovery. Before the first recovery mutation, persist an external fence bound to that revision, image identity, and operation. After that fence, retries must use the same candidate; reopening a previous image is allowed only before recovery starts. Serialize concurrent host-local deployments and retain the fence until readiness.
- Release archives must select the published immutable image digest and support installation without a source checkout or local build. Configuration initialization refuses to overwrite existing operator files.
- Backup verification uses a separate Compose Project, database port, configuration, and authority volume. Before any destructive reset, verify the exact operator-provisioned ownership label on every target volume and container; missing, mixed, or unreadable ownership fails closed. Never reset the live authority as a verification target.
- Export TTL cleanup requires operator scheduling of `cloud-reconcile-exports`; the one-shot service receives only the live authority and export artifact storage it needs.
