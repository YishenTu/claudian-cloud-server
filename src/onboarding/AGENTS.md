# Onboarding

- Staging is isolated and expiring; it cannot create a canonical placement or become a normal traffic source through filesystem observation. Project authority owns activation and cancellation settlement.
- The private-development two-device flow requires the LAN Host to be manually stopped and both trusted reports to match. Before activation, only the source actor may begin, upload, activate, or cancel; each accepted actor may submit only its own immutable report. Ordinary Project admission takes over at activation.
- Development assertions, manually stopped Host assumptions, and LAN Host-transfer bindings cannot establish production Cloud transfer authority.
- Production staging owns artifact receipt, validation, expiry, and exact cleanup. Transfer authorization, claims, relinquishment proof, publication, and recovery remain with the lifecycle owner.
- Reused staging mechanics must preserve an exact profile-bound identity. Reservation detachment releases temporary admission without deleting recovery-owned content.
- An export delivery marker is cleanup metadata, not authority to delete staging. Cleanup remains blocked until the exact lifecycle journal is terminal or its Project tombstone proves authority removal; immutable backup retention is separate.
